# Customizing this app for your organization

Everything an organization needs to change to run its own e-Namecard lives in
this folder plus a handful of environment variables. You should never need to
edit application code under `src/` to rebrand or redeploy.

## 1. Organization identity — `org.ts`

Edit [`org.ts`](./org.ts). It drives every piece of org-specific text and
metadata in the app:

| Field             | Used for                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `appName`         | Browser tab titles, PWA name, page headings                                                                             |
| `appShortName`    | Site header label, PWA `short_name`                                                                                     |
| `appDescription`  | Meta description, PWA manifest description                                                                              |
| `orgName`         | UI copy ("Example Organization staff? Sign in…", footer)                                                                |
| `orgLegalName`    | Default `ORG` value on generated vCards                                                                                 |
| `emailDomain`     | The `@example.com` suffix hint shown next to the lookup field (display only — sign-in is governed by your Entra tenant) |
| `website`         | Default website on vCards when a staff card leaves it blank                                                             |
| `address`         | Default postal address on vCards when left blank                                                                        |
| `themeColor`      | PWA/browser theme color — keep equal to `--color-brand-500`                                                             |
| `backgroundColor` | PWA splash/background color                                                                                             |
| `logoAlt`         | Alt text for the brand logo                                                                                             |

The file is validated at startup (`src/config/orgSchema.ts`); a bad value fails
the boot with a readable error. **Never put secrets here** — this file is
bundled into the browser.

## 2. Colors and fonts — `theme.css`

Edit [`theme.css`](./theme.css). The `--color-brand-*` scale (50–900) is what
every `brand-*` Tailwind utility in the app resolves to. Generate a scale from
your primary brand color with any Tailwind palette generator (e.g.
uicolors.app) and paste it in. The font stack is customizable in the same file.

Remember to mirror your `--color-brand-500` into `themeColor` in `org.ts`.

## 3. Logo and icons — `public/brand/`, `public/icons/`

Drop in your own assets (paths and filenames must stay the same):

- `public/brand/logo.png` — square brand logo master, 1024×1024, transparent
  background. Shown in the header, landing page, and cached for offline QR
  rendering.
- `public/brand/qr-logo.png` — the QR center overlay. Regenerate it from your
  `logo.png` with:

  ```bash
  node scripts/make-qr-logo.mjs
  ```

  It bakes your logo onto a radial white plate that fades out at the edge so
  it blends into the QR dots. The QR uses error-correction level H, which
  tolerates the overlay.

- `public/icons/icon-192.png`, `public/icons/icon-512.png` — PWA install
  icons (192×192 and 512×512).

The repo ships with neutral placeholder assets generated by
`scripts/make-brand-assets.mjs` — replace them before going to production.

## 4. Hostname (FQDN) — environment

The public origin is configured, not hardcoded. In your production `.env`:

```
AUTH_URL=https://namecard.example.com
```

OIDC redirects, Secure cookies, and absolute URLs embedded in QR vCards
(`PHOTO;VALUE=URI:https://…/avatar/<slug>`) are all derived from `AUTH_URL`.
Point your reverse proxy at the app and make sure `X-Forwarded-Proto` /
`X-Forwarded-Host` are passed through (see `docs/deploy/`).

## 5. Microsoft 365 / Entra ID — environment

Register your own Entra ID application (step-by-step guide:
`docs/deploy/entra-app-registration.md`) and configure it via `.env`:

```
AUTH_MICROSOFT_ENTRA_APPLICATION_ID=<app registration client id>
AUTH_MICROSOFT_ENTRA_ID_SECRET=<client secret>
AUTH_MICROSOFT_ENTRA_ID_ISSUER=https://login.microsoftonline.com/<tenant-id>/v2.0
ADMIN_GROUP_ID=<object id of the security group allowed into /admin>
AUTH_SECRET=<openssl rand -base64 32>
```

The issuer must be tenant-specific (never `common`/`organizations`) — only
accounts from your tenant can sign in. See `.env.example` for the full list
including `DATABASE_URL`.

## Checklist for a new deployment

1. Fork/clone the repo.
2. Edit `customization/org.ts` and `customization/theme.css`.
3. Replace `public/brand/logo.png` and PWA icons; run `node scripts/make-qr-logo.mjs`.
4. Create the Entra app registration; fill in `.env` (copy from `.env.example`).
5. Set `AUTH_URL` to your FQDN and configure your reverse proxy.
6. Deploy with Docker Compose (`docs/deploy/production-guide.md`).
